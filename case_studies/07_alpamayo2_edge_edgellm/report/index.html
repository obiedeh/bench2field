Where a decision's time goes

Stage medians, stream-synchronized at each boundary as the recipe's own runner does. The chain of causation is greedy decoding, one token at a time; the recipe's speculative drafter is not released for the Edge model.

vision encoderprefillchain of causationaction expertexpert K/V copy

With no reasoning at all the floor is vision, prefill and expert: about 155 ms at one candidate, already above Embedl's published median. Each token of reasoning costs 10.8 ms of GPU work (measured with the engine alone, with and without a host sync per token), so a 22-token sentence is about 237 ms of the decision. The NVFP4 engine holds 1.62 GB of packed weights against 1.98 GB in FP8, yet its token costs 15.0 ms on the example clip against 11.0 in FP8: on Edge-LLM 0.11.1 with TensorRT 10.13.3.9 the single-token NVFP4-A16 kernel does not turn halved bytes into time, and W4A16 adds dequantization work to the compute-bound prefill.

What each change bought

  • NVIDIA's recipe on the Jetson boardTail 544 to 427 ms against the PyTorch stream; median 331 to 367 ms, so no gain at the median.
  • Vision cache across decisionsVision stage 98 to 27 ms; p95 613 to 525 ms and 8 J less per decision against encoding all 22 frames; the median moved only 9 ms because the cold run decoded faster on that clip (example clip, six candidates).
  • One candidate instead of sixExpert 83 to 34 ms; decision 413 to 367 ms median.
  • Three Euler steps instead of fiveExpert 34 to 25 ms; median 367 to 353 ms; trajectories within 0.2 m of five steps on eight clips, 0.6 m on one.
  • NVFP4 W4A16 language modelDecode 11.0 to 15.0 ms per token on the example clip, prefill 95 to 124 ms, vision 25 to 33 ms. The engine file is smaller (1.62 against 1.98 GB), so the weights are packed; the single-token kernel on this stack does not turn the bytes into time.
  • Token kept on the GPU, end of chain checked per chunk286 ms decode against 242: no change. The host round trip was never the cost.

Issues found, with causes

In the order they happened. The full log with times is FRICTION_LOG.md.

  • 1. The recipe's submodule step must be recursivecmake stopped on a missing xgrammar header: Edge-LLM's own submodules were absent.Fetched recursively, copied 3rdParty to the board.
  • 2. nvcc from the `cuda` alternative against CUDA 13.0 headersThe toolchain forces /usr/local/cuda/bin/nvcc, 13.2 on this board; its launch stubs do not match 13.0's host_runtime.h, every CUDA file failed.nvcc pinned to the 13.0 toolkit, CUDA_DIR and cuRAND include set to match.
  • 3. Action engine fixed at six candidatesA one-candidate export writes candidates_per_sequence 2; the builder computes zero sequences and TensorRT rejects the profile.Set candidates_per_sequence to 1 in the one-candidate config.
  • 4. Shim renames MLP layers, copies the quantization config verbatimA MIXED_PRECISION (NVFP4) config loses every per-layer entry; the exporter treats packed weights as FP16 and torch.export fails on a shape mismatch.Rewrote the config keys with the same renames, dropped modules restored to FP16.
  • 5. NVFP4-A16 GEMM kernels need the CuTe DSL build flagNvfp4A16BlackwellGemmRunner::isSupported is false unless the plugin is built with ENABLE_CUTE_DSL=ALL; the recipe's build script leaves the default.Reconfigured with the kernel groups on; the W4A16 engines built.
  • 6. TensorRT 10.13 cannot build the W4A4 graphMyelin stops on PLUGIN_V3 with empty producers; the recipe pins TensorRT 11.3.Parked; a newer TensorRT (JetPack 7.2.2) is the owner's call.
  • 7. A probe reported 1.1 ms per decode tokenA timing bug in the probe (start time reset per iteration). The corrected figure is 11.8 ms, and the wrong number was withdrawn the same hour.Probe fixed; both numbers kept in the friction log.

What stands between this build and the published 92 ms

  • A speculative drafterNVIDIA's 220 ms uses a DFlash2 drafter that is not part of the model release. Greedy decoding costs 10.8 ms per token here; a drafter verifies several tokens per weight read. Training one with NVIDIA's SpecForge recipe is a project of its own.
  • A working FP4 decode pathW4A16 is slower on this stack and W4A4 does not build on TensorRT 10.13.3.9. A newer TensorRT (JetPack 7.2.2) is the next thing to try, and a system change for the owner to decide.
  • A shorter prefill95 ms of every decision re-encodes a prompt in which old and new camera frames interleave per camera, so unchanged frames are not a cacheable prefix. A prompt layout that keeps them contiguous, or Edge-LLM's media-aware K/V reuse, is the lever.
